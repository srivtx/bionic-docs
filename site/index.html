03Formats

Two paths, one fixation step

A document is sniffed by its first bytes and sent down one of two paths. Both end with plain text in text nodes, so the emphasis step is format-agnostic.

PDF

Recognised when the first four bytes are %PDF.

  • The locally bundled PDF.js reads the text layer with isEvalSupported: false and useSystemFonts: true. Content streams are never executed.
  • src/pdf/lines.ts groups text items into lines: a new line starts on hasEOL or a vertical jump, whitespace runs collapse, and items are joined with a space only when neither side has one. It has no PDF.js import, so it is unit-tested directly.
  • One section per page as .pdf-page, one paragraph per line as .pdf-line. A page with no text layer renders empty rather than guessed at.

EPUB

Recognised when the first two bytes are PK.

  • Unzipped in memory with fflate. Nothing is written to disk and nothing is fetched. container.xml gives the OPF rootfile; the OPF gives the title, manifest and spine order.
  • The table of contents comes from the EPUB3 navigation document, or the EPUB2 NCX when there is none.
  • Each chapter is sanitized before insertion: script, style, iframe, object, embed, link, meta and base are removed, every on* attribute is removed, and javascript: URLs are stripped.

05How it works

Sniff, parse, emphasize

Three moves, all of them on your machine. The reader page is the only place a document is ever parsed.

1.

Sniff the bytes

The first bytes decide the path: %PDF goes to the PDF parser, PK to the EPUB parser. A file you drop is read from disk with the File API.

2.

Parse or unzip

A PDF’s text layer is rebuilt into lines with the bundled PDF.js. An EPUB is unzipped in memory and each chapter is sanitized before it is rendered.

3.

Emphasize, reversibly

The chosen mode bolds the leading letters of every word. Changing the mode or intensity re-renders the chapter, and processed nodes are tracked in a WeakSet so it stays idempotent.

06Architecture

What runs, and where the bytes go

The interesting constraints here are not performance but provenance: which code runs, and where a document’s bytes are allowed to travel.

module map — bionic-docs
#support, then the parsers, then the surfaces
$src/shared/ types, cross-browser shim, storage
$src/core/ pure fixation algorithm — DOM-free, tested
$src/pdf/ lines.ts (pure) + pdf.ts (PDF.js render)
$src/epub/ parse.ts (unzip, OPF, TOC, sanitize) + epub.ts
$src/reader/ the document reader page
$src/popup/ open a document, quick settings
$src/options/ full settings, live preview, import/export
$src/background/ open-current command and message handling

Invariants the build enforces

  • On-device. The only network call loads the document you opened. A security test fails the build if fetch, eval, new Function, document.write, remote URLs, XMLHttpRequest or WebSocket appear anywhere in src/ except that one fetch.
  • No remote code. PDF.js, fflate and the application are bundled; the manifest declares no external scripts.
  • Sanitize before render. EPUB chapters are cleaned before insertion, not after.
  • One manifest source. scripts/manifest.mjs feeds the build and is asserted by a test.

The core contract

  • Every format-specific path ends at the same frozen interface, so the fixation algorithm is written once and has no idea what a PDF is.
  • PDF text is treated as plain text and placed into new text nodes; the original layout is not reproduced and not trusted.
  • src/pdf/lines.ts imports nothing from PDF.js, so line reconstruction is unit-tested directly.
  • The popup never parses anything: it asks the background page to open the reader, and parsing happens only there.

07Limits

What it does not do

The limitations are part of the contract, not footnotes.

Out of scope

  • Scanned PDFs have no text layer and render as empty pages. OCR is out of scope in this version.
  • The original layout is not reproduced. Complex multi-column or design-heavy pages read in extraction order.
  • EPUB rendering is intentionally minimal: no pagination and no book CSS beyond the sanitized chapter markup.
  • Closed shadow roots in a chapter cannot be reached, and are left alone.

If a document has a real text layer, it works.

What it does handle

  • PDF and EPUB, sniffed by magic bytes rather than by file extension.
  • Multi-page PDFs and multi-chapter EPUBs, with the table of contents read from the navigation document or the NCX.
  • Resuming: the last page or chapter is remembered per document, keyed by a content fingerprint rather than a URL.
  • Keyboard-free reading: Ctrl/Cmd + Shift + O opens the current document at any time.

Both engines build from one source tree, so they cannot drift apart.

09Privacy

There is no server.

bionic-docs is a local reading aid for documents. The extension makes no network requests for content, has no analytics, and has no account. It does not keep your documents.

What is stored. Two things, using the extension’s storage permission: your reading settings — mode, intensity, minimum word length, appearance — and the last page or chapter you were on for each document, so the reader can offer to resume. That remembered position is a page or chapter index keyed by a content fingerprint of the document (a hash of its length and bytes), not its URL. No document bytes and no document text are stored.

What is read, and when. A file you choose or drop is read from disk with the File API and parsed in the extension page. The only fetch in the entire codebase loads a document URL you explicitly opened, such as a PDF already in a tab. Nothing is uploaded, and nothing is retained after you close the reader page: the bytes are read into memory, parsed, and released.

Why it asks for host access. Opening a document at a URL and reading the current tab’s URL for the open-current command both need it. Page content is never read for any other reason.

No remote code. PDF.js and fflate are bundled into the package; nothing is fetched or evaluated at runtime. PDF.js is constructed with isEvalSupported: false. EPUB chapters are sanitized before insertion: script, style, iframe, object, embed, link, meta and base are removed, every on* attribute is removed, and javascript: URLs are stripped from href and src.

How to verify it. tests/security.test.ts fails the build if fetch, eval, new Function, document.write, innerHTML assignment, remote URLs, XMLHttpRequest or WebSocket appear anywhere in src/, except the single reader fetch. src/shared/browser.ts is the only module that touches the extension API namespace, and scripts/manifest.mjs is the single source of the permission list.

Revoking access. Turning the extension off, disabling it, or removing it stops all processing immediately. Removing the extension deletes its stored settings and positions.

10Install

Build it from source

Store listings are pending. Build both targets from one source tree, then load the unpacked extension.

terminal — bionic-docs
$git clone https://github.com/srivtx/bionic-docs
$cd bionic-docs && bun install
$bun run build
#Chrome/Edge: chrome://extensions → Developer mode → Load unpacked → dist/chrome
#Firefox: about:debugging → This Firefox → Load Temporary Add-on → dist/firefox/manifest.json

Once built, press Ctrl/Cmd + Shift + O to open the current document at any time. Requires Chrome 116 or newer, or Firefox 140 or newer — the Firefox floor is 140 because data_collection_permissions is only understood from that version. Releases are on GitHub.
