Security

Privacy

This page is the exact threat model in plain language. Bionic Docs parses untrusted documents inside an extension page and never runs code from them. The extension is as strict about the network as it asks you to be about your files.

What it never does

  • No remote code. PDF.js, fflate, and all application code are bundled in the package; nothing is fetched and evaluated at runtime.
  • No content leaves the device. There is no server. The only fetch in the codebase is the reader loading the document URL the user explicitly opened.
  • No analytics, no telemetry, no accounts.
  • No declarativeNetRequest, webRequest, cookies, history, or downloads.

The single fetch

There is exactly one network call in the extension, and it happens only because you asked for it. When you use Open current document on a PDF in a tab, the reader fetches that URL to get its bytes. A file you pick or drag is read from disk with the file input and never fetched. No URL you did not open is ever requested.

Permissions

Every permission the manifest requests, and why.
PermissionWhy
storageSave the reading settings and the last reading position per document.
activeTabRead the active tab's URL to open a PDF in the reader.
<all_urls> (host)Fetch the document the user opened. Extensions need host access to read a cross-origin file.

Document handling

  • EPUB chapters are sanitized before insertion: script, style, iframe, object, embed, link, meta, base, all on* attributes, and javascript: URLs are removed.
  • PDF text is treated as plain text and placed into new text nodes; PDF content streams are never executed.
  • PDF.js is constructed with isEvalSupported: false.
  • No document bytes are kept after you close the reader page. Two things are persisted: the reading settings, and a small position map that remembers the last page or chapter per document. Each position is keyed by a content fingerprint — a short hash of the document's kind, byte length and bytes — not by the document's URL. The map stores the fingerprint, a page or chapter index, and a timestamp used only to evict the oldest entry; it never stores document bytes or text. It is capped at 25 documents, oldest evicted first.

The anti-network test gate

A source scan in bun test fails the build if eval, new Function, document.write, innerHTML assignment, remote URLs, or network calls appear anywhere in the project's own src/, except the single reader fetch. That means the privacy claim is enforced by CI, not just documented.

bun test
bun run build
node scripts/verify-build.mjs
bunx web-ext lint --source-dir dist/firefox

web-ext lint reports warnings (DANGEROUS_EVAL, UNSAFE_VAR_ASSIGNMENT) that originate in the vendored PDF.js bundle. The eval path is disabled at runtime by isEvalSupported: false. The build passes with zero lint errors.

What this does not cover

This is a threat model for the extension, not for your machine. A compromised browser profile, a malicious extension you installed alongside this one, or a modified build are outside it. If you did not build it yourself, verify the source you loaded.

Reporting

Open a private security advisory on the repository (Security → Report a vulnerability). Include a minimal reproduction and the browser version.
