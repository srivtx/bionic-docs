Architecture

A small extension in which the interesting constraints are not performance but provenance: what code runs, where document bytes go, and why no existing product satisfies the whole clause.

Module map

The source tree is split so that the pure parts are testable without a browser and the document parsers never reach for the network.

src/
  shared/     types, cross-browser shim, storage (no document parsing)
  core/       pure fixation algorithm (DOM-free, tested)
  pdf/        lines.ts (pure line reconstruction) + pdf.ts (PDF.js + render)
  epub/       parse.ts (unzip, OPF, TOC, sanitize) + epub.ts (render + fixation)
  reader/     reader.html/css/ts — the document reader page
  popup/      toolbar popup: open a document, quick settings
  options/    full settings, live preview, import/export
  background/ open-current command and message handling

Document flow

popup ──open-current──▶ background ──▶ reader.html?src=<url>
reader
  ├─ sniff magic bytes: %PDF → pdf.ts ;  PK → epub.ts
  ├─ pdf.ts:  PDF.js getTextContent → lines.ts groupLines → fixation
  └─ epub.ts: fflate unzip → container.xml → OPF (title/spine/nav|ncx)
              → sanitizeChapter → fixation

The popup never parses anything. It sends {type:"open-current"} to the background, which resolves the active tab and opens the reader with a source URL or the file picker. Parsing happens entirely in the reader page.

Invariants

  1. On-device. The only network call loads the document the user opened. tests/security.test.ts fails the build if fetch, eval, new Function, document.write, innerHTML assignment, remote URLs, XMLHttpRequest, or WebSocket appear anywhere in src/ except the single reader fetch.
  2. No remote code. PDF.js, fflate, and the application are bundled; the manifest declares no external scripts.
  3. Sanitize before render. EPUB chapters are sanitized — scripts, handlers, and remote or javascript: URLs removed — before insertion.
  4. Deterministic text. PDF text is treated as plain text and placed into new text nodes; PDF.js runs with isEvalSupported: false.
  5. Pure line reconstruction. src/pdf/lines.ts has no PDF.js import, so it is unit-tested directly.
  6. One manifest source. scripts/manifest.mjs feeds build.mjs and is asserted by tests/manifest.test.ts.

The core contract

Everything format-specific ends at one frozen interface. The fixation algorithm is DOM-free and shared, byte-for-byte, with the sibling extension.

export interface BionicOptions {
  mode: ModeId; intensity: number; minWordLength: number;
  skipCommonWords: boolean; rule: string; customVowels: string;
}
export function boldLength(word: string, options: BionicOptions): number;
export function emphasize(word: string, options: BionicOptions): { head: string; tail: string } | null;
export function bionicText(text: string, options: BionicOptions): string;

Ownership is explicit: EPUB, the preferences UI, and the tests each have an owner; the PDF path, the reader, and the build are the orchestrator's. This page and the codebase read from the same documents in docs/.

Why the package is shaped this way

  • Chrome's built-in PDF viewer is a privileged component an MV3 content script cannot inject into. The workable architecture, used by every credible competitor, is to bundle PDF.js locally and present the document in the extension's own reading view.
  • PDF.js and fflate are ordinary local JavaScript; bundling them satisfies MV3's no-remote-code rule.
  • Text positioning comes from page.getTextContent() item transforms — the same signal Bionic-for-Zotero patches.

Prior art, and the gap

The clause nobody satisfies, as researched and verified on 2026-09-19 in docs/PRIOR-ART.md:

Applies bionic-style fixation emphasis to the text of PDF and EPUB documents entirely on-device — no upload, no remote API, no account — in a single Manifest V3 extension shipped for Chrome and Firefox.

Every existing product fails at least one qualifier. The two facts that matter most: the 100K-user incumbent posts extracted page text to its own API, and the only store product that handles files is cloud, paid, and Chromium-only.

Verified competitors, from docs/PRIOR-ART.md (researched 2026-09-19).
ProductWhat it doesWhy it fails the clause
Bionic Reading (official Chrome extension, 100K users, v5.0.2) Bionic emphasis on web pages. Sends the extracted article text to api.reader.bionic-reading.com (verified by an independent extension audit, 2026-08-28); no PDF or EPUB; rated 2.4–2.5 stars.
Nook — Focused Reading Bionic and RSVP on PDF, EPUB, DOCX, and web. Cloud and subscription, Chrome and Edge only, about 289 users.
ReadClear (Read Aloud — Dyslexia Font, Bionic Reading) Bionic plus PDF. Calls clearread-api-production.up.railway.app, Chrome only, about 251 users.
Readit Fast PDF and EPUB speed reading. PDF support is gated behind account sign-in.
FastRead PDF and EPUB to bionic. Web app; documents are uploaded, not read locally in the browser.
Readability Reader Local PDF.js reading view, MV3, Chrome and Firefox. No fixation emphasis.
webextension.org PDF Reader Replaces the PDF viewer with local PDF.js. No fixation emphasis.
Bionic for Zotero Fixation glyphs inside Zotero's PDF.js. Native Zotero only, not a browser extension.
Bionic Reader (Rain Jr., Firefox) Web-page bionic. No PDF or EPUB.
Local accountless bionic web extensions (LucidRead, Elu, FocusFlow, and the sibling bionic-page) Web articles. No PDF or EPUB.

Threat to the thesis

The gap is a current fact, not a permanent one. If the official Bionic Reading extension adds local PDF and EPUB, or a local cross-browser reader adds fixation, the gap closes. docs/PRIOR-ART.md is the file to update when that happens; re-check the rows above before shipping a store listing.
