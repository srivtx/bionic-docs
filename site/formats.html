Reference

Formats

A document is sniffed by its first bytes and sent down one of two paths. Both paths end in the same fixation step, because both end with plain text in text nodes.

reader.html?src=…
  ├─ sniff: %PDF → pdf.ts ;  PK → epub.ts
  ├─ pdf.ts:  PDF.js getTextContent → lines.ts groupLines → fixation
  └─ epub.ts: fflate unzip → container.xml → OPF (title/spine/nav|ncx)
              → sanitizeChapter → fixation

PDF

A PDF is recognized when its first four bytes are %PDF. The bytes are handed to the locally bundled PDF.js, constructed with isEvalSupported: false and useSystemFonts: true. PDF content streams are never executed.

For each page, getTextContent() returns text items in content order, each with a transform. src/pdf/lines.ts is a pure function with no PDF.js import, so it is unit-tested directly. It groups items into lines:

  • a new line starts when the item has hasEOL or the vertical position jumps by more than roughly half the glyph height (max(2, height * 0.6));
  • runs of whitespace inside a line are collapsed to a single space and the line is trimmed;
  • items are joined with a space when neither side already has one.

The reader renders one section per page with the class pdf-page and one paragraph per line with the class pdf-line. A page with no extractable text gets a single paragraph saying so; a scanned page, which has no text layer, therefore renders as empty rather than guessed at.

EPUB

An EPUB is recognized when its first two bytes are PK. It is unzipped in memory with fflate (unzipSync); nothing is written to disk and nothing is fetched.

  1. META-INF/container.xml is read for the OPF rootfile path.
  2. The OPF package gives the title, the manifest of items, and the spine order that defines chapters. Hrefs are resolved relative to the OPF directory, with fragments and queries stripped.
  3. The table of contents comes from the EPUB3 navigation document (the manifest item with properties="nav", the nav with epub:type="toc") or, if absent, from the EPUB2 NCX navMap.
  4. Each spine chapter is parsed and sanitized before it is inserted: the elements script, style, iframe, object, embed, link, meta, and base are removed, every on* attribute is removed, and javascript: URLs are stripped from href and src. Nothing else is rewritten.
  5. The chapter is rendered into a epub-chapter container and its first heading is surfaced as epub-title for the reader toolbar.

Changing the mode or intensity re-renders the current chapter with the new options. Processed text nodes are tracked in a WeakSet so applying the same options twice is idempotent.

Why the two paths converge

PDF extraction and EPUB section parsing both produce the same thing: text in ordinary text nodes. The fixation step is then format-agnostic. For each token it calls emphasize() from src/core/algorithm and wraps the emphasized head in <b class="bp-head">; in the low-distraction mode it also wraps the remainder in <span class="bp-tail">. It skips script, style, code, pre, kbd, samp, and textarea, and anything marked data-bionic="off".

There is exactly one fixation implementation. The extension and this site both run it; the site's copy is compiled from the same sources by scripts/build-demo.mjs, so it cannot drift.

Limits, per format

What each path does and does not preserve.
ConcernPDFEPUB
LayoutNot preserved. Lines are reflowed into one column, in extraction order.Preserved as text flow; original book CSS is not applied.
ImagesNot shown; only the text layer is read.Not shown; only the sanitized chapter markup is inserted.
Scanned pagesNo text layer means an empty page. There is no OCR.Not applicable.
NavigationPage by page, in document order.By visible chapter, in spine order.
Active contentContent streams are never executed; text is plain text.Sanitized: scripts, handlers, and javascript: URLs removed.

Reflow means a two-column paper can read in an unexpected order, and a table can lose its alignment. That is the trade for reading a PDF as text with fixation rather than only as rendered pages.
